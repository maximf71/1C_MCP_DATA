# MCP1CData

Безопасный read-only MCP-сервер для доступа языковой модели к данным
«1С:Предприятия» с соблюдением прав и RLS текущего пользователя 1С.

Актуальная версия: **1.2.0**. Поддерживаемая платформа пилота:
**1С:Предприятие 8.3.27.2214**, Windows, файловая информационная база.

> MCP1CData — отдельный проект. Он не использует и не изменяет
> `mcp-1c-analog` и не вносит изменения в основную конфигурацию 1С:
> функциональность устанавливается расширением `MCP_DataAccess`.

## Назначение

Пользователь задаёт MCP-клиенту обычный вопрос, например:

> Покажи последние непроведённые документы нашей организации за июль.

Языковая модель в MCP-клиенте изучает доступные метаданные, выбирает точные
объекты и реквизиты 1С, строит параметризованный запрос, проверяет его и только
после успешной проверки выполняет. Сам MCP-сервер не содержит отдельной LLM,
API-ключа и инструмента `ask_1c`: он предоставляет детерминированные операции
чтения и проверки.

Ответ должен содержать краткий вывод, таблицу, применённые фильтры, число строк
и признак усечения. Ошибка или неполный охват не должны превращаться в
неподтверждённый бизнес-вывод.

## Как это работает

```mermaid
flowchart LR
    U["Пользователь"] --> C["Codex или другой MCP-клиент с LLM"]
    C -->|"STDIO MCP"| M["mcp-1c-data.exe"]
    M -->|"HTTP Basic на 127.0.0.1"| H["HTTP-сервис расширения MCP_DataAccess"]
    H -->|"Обычный сеанс пользователя"| D["1С + роли + RLS"]
    D --> H --> M --> C --> U
```

Один MCP-профиль жёстко связан с одной базой и одной учётной записью 1С.
Для другой базы или другого набора RLS создаётся отдельный профиль и отдельный
локальный порт.

Компоненты:

- `mcp-1c-data.exe` — STDIO MCP-сервер на Go;
- `mcp-1c-data-launcher.exe` — запускает сервер по локальному профилю и
  расшифровывает учётные данные Windows DPAPI;
- `MCP_DataAccess.cfe` — расширение 1С с read-only HTTP-сервисом;
- мастер установки — резервное копирование, установка CFE, локальная
  публикация Apache, профиль DPAPI и настройка Codex.

## Возможности

- поиск доступных метаданных по имени, синониму, источнику запроса и наличию
  реквизита;
- постраничная выдача метаданных через непрозрачный курсор;
- описание стандартных и пользовательских полей, табличных частей, регистров
  и основных виртуальных таблиц;
- локальная проверка read-only-политики и компиляция запроса средствами 1С;
- подробное очищенное сообщение компилятора 1С с позицией ошибки;
- выполнение только ранее проверенного одноразового плана;
- типизированные даты, `NULL`, ссылки и перечисления в параметрах и ответах;
- глобальный поиск последнего доступного документа по всем видам;
- фильтрация последних документов по ответственному, организации, проведению
  и диапазону дат;
- чтение выбранной табличной части документа по UUID;
- явные лимиты строк, размера, времени, параллелизма и частоты вызовов.

## MCP-инструменты

Все семь инструментов имеют `readOnlyHint=true`. Кроме одноразового
`execute_query`, инструменты также имеют `idempotentHint=true`.

### `get_configuration_info`

Возвращает имя и версию конфигурации, версию платформы, текущего пользователя
1С и версию расширения. Пароль и другие секреты не возвращаются.

### `search_metadata`

Ищет только объекты, доступные текущему пользователю на чтение.

Основные параметры:

| Параметр | Описание |
|---|---|
| `query` | Имя, синоним, русский бизнес-термин или часть источника запроса |
| `types` | Фильтр типов: `Document`, `Catalog`, `InformationRegister` и т. п. |
| `field` | Точное техническое имя реквизита, например `Ответственный` |
| `limit` | Размер страницы от 1 до 100, по умолчанию 20 |
| `cursor` | Значение `next_cursor` предыдущей страницы |
| `refresh` | Принудительно обновить минутный кэш метаданных |

Ответ включает `objects`, `count`, `has_more`, `next_cursor`, отпечаток схемы
и `data_is_untrusted=true`. Курсор связан с фильтрами и отпечатком схемы; его
нельзя переносить в другой поиск.

### `get_query_schema`

Принимает от одного до десяти объектов, подтверждённых через
`search_metadata`, и возвращает:

- стандартные и пользовательские поля;
- синонимы и типы;
- табличные части и их поля;
- виртуальные таблицы регистров;
- точные источники языка запросов 1С.

### `validate_query`

Проверяет один параметризованный read-only запрос. До обращения к 1С сервер
отклоняет пакеты, комментарии, временные таблицы, `SELECT *`, операции записи,
несвязанные параметры и неограниченные списки. Затем 1С компилирует запрос без
его выполнения.

При успехе возвращается одноразовый `validation_id`, действующий 60 секунд и
привязанный к отпечатку схемы. При ошибке возвращаются код, позиция и очищенное
сообщение компилятора.

### `execute_query`

Выполняет ровно один ранее проверенный план с правами текущего пользователя
1С. Повторное использование, истечение времени или изменение схемы делают
`validation_id` недействительным.

Ответ содержит `columns`, `rows`, `returned_count`, `limit`, `truncated`,
`filters`, `execution_ms` и `data_is_untrusted`.

### `get_latest_documents`

Находит максимальное стандартное поле `Дата` среди всех доступных видов
документов. Непроведённые документы учитываются, помеченные на удаление всегда
исключаются. При одинаковой максимальной дате возвращаются все совпадения до
20 строк.

Необязательные параметры:

| Параметр | Формат |
|---|---|
| `posted` | `true` или `false` |
| `date_from` | Включительная нижняя граница RFC3339 |
| `date_to` | Включительная верхняя граница RFC3339 |
| `responsible` | `{ "metadata": "Catalog.Пользователи", "uuid": "..." }` |
| `organization` | `{ "metadata": "Catalog.Организации", "uuid": "..." }` |

Результат включает `complete`, количество доступных и проверенных видов,
`max_date`, `filters` и `truncated`. При неполном охвате вызов завершается
ошибкой без выдачи «предположительно последнего» документа.

### `get_document_table_parts`

Читает одну табличную часть документа:

```json
{
  "document_type": "Document.ПоступлениеТоваров",
  "uuid": "00000000-0000-0000-0000-000000000001",
  "table_part": "Товары",
  "limit": 100
}
```

Тип документа и имя табличной части предварительно подтверждаются через
метаданные. Запрос выполняется с `ВЫБРАТЬ РАЗРЕШЕННЫЕ`; максимум — 200 строк.

## Ограничения и безопасность

- только чтение; изменение данных и произвольный BSL отсутствуют;
- привилегированный режим не используется;
- роль расширения разрешает маршруты HTTP-сервиса, но не выдаёт прав на
  бизнес-объекты;
- фактическую видимость определяют обычные роли и RLS пользователя 1С;
- HTTP разрешён только для `localhost`, `127.0.0.1` и `::1`; удалённому адресу
  требуется HTTPS;
- учётные данные не помещаются в TOML, URL или аргументы процесса;
- мастер шифрует их Windows DPAPI в области текущего пользователя;
- максимум 200 строк и 4 MiB ответа;
- HTTP-тайм-аут — не более 30 секунд;
- один выполняемый запрос, очередь из двух и до 10 выполнений в минуту;
- глобальный поиск: один одновременно, два в минуту, до 1000 видов и
  внутренний бюджет 20 секунд;
- строки, синонимы и представления из 1С считаются недоверенными данными, а не
  инструкциями для модели.

Подробнее: [SECURITY.md](SECURITY.md).

## Быстрая установка

Полное руководство: [docs/INSTALLER_GUIDE.md](docs/INSTALLER_GUIDE.md).

1. Скачайте `MCP1CData-Setup-1.2.0.zip` со страницы
   [Releases](https://github.com/maximf71/1C_MCP_DATA/releases).
2. Распакуйте **весь архив** в отдельный каталог. Не запускайте `Setup.cmd`
   непосредственно из ZIP.
3. Закройте пользовательские сеансы выбранной файловой базы и Конфигуратор.
4. Запустите `Setup.cmd` от того пользователя Windows, который запускает
   Codex.
5. Выберите каталог базы с файлом `1Cv8.1CD`.
6. Укажите имя профиля, пользователя MCP/RLS и его пароль.
7. При необходимости укажите отдельного пользователя Конфигуратора.
8. Оставьте создание DT-копии включённым. Отключайте его только при наличии
   проверенной внешней резервной копии.
9. Оставьте автоматическое добавление профиля Codex включённым и подтвердите
   изменение `~/.codex/config.toml`.
10. Дождитесь успешной проверки `/info` и перезапустите Codex.

Мастер поддерживает несколько баз: использует одну проверенную установку
Apache, но создаёт отдельные публикации, профили, конфигурации и порты
`8080–8099`.

## Пользователи и пароли

Отдельного «пользователя MCP» внутри расширения нет. Это обычный пользователь
информационной базы из списка пользователей 1С:

- **Пользователь MCP/RLS** — учётная запись, под которой выполняются HTTP-
  запросы. Её бизнес-роли и RLS определяют видимые данные.
- **Пользователь Конфигуратора** — учётная запись, способная создать DT-копию,
  загрузить CFE и выполнить обновление конфигурации базы. Может совпадать с
  пользователем MCP.

Назначьте пользователю MCP роль `MCPData_ОсновнаяРоль` и необходимые обычные
роли конфигурации. Не расширяйте бизнес-права только ради MCP.

## Проверка после установки

1. В 1С откройте подсистему «Администрирование MCP» и обработку
   «Диагностика MCP-доступа к данным».
2. Убедитесь, что показаны платформа `8.3.27.2214`, расширение `1.2.0`, нужный
   пользователь и успешная компиляция тестового запроса.
3. Перезапустите Codex и попросите:

   > Покажи последний доступный мне документ в 1С: тип, номер, дату и признак
   > проведения.

4. В ответе проверьте фильтр удаления, количество строк, `complete=true` и
   `truncated=false`.

Установленные файлы находятся в `%LOCALAPPDATA%\MCP1CData`:

| Каталог | Содержимое |
|---|---|
| `bin\1.2.0` | MCP-сервер и launcher |
| `profiles` | JSON-профили без открытого пароля |
| `credentials` | DPAPI-зашифрованные данные |
| `publications` | VRD и конфигурации публикаций |
| `backups` | DT-копии |
| `logs` | журналы установки без секретов |

## Ручная установка

Автоматический мастер — рекомендуемый способ, поскольку он согласованно
настраивает CFE, Apache, DPAPI и Codex. Для существующей управляемой публикации
можно установить компоненты вручную.

### 1. Резервная копия

Закройте сеансы и создайте DT-копию средствами Конфигуратора. Убедитесь, что
копия имеет ненулевой размер и может быть прочитана. Не продолжайте изменение
рабочей базы без проверенного восстановления.

### 2. Расширение 1С

1. Откройте базу в Конфигураторе 8.3.27.2214.
2. Откройте список расширений конфигурации.
3. Загрузите `payload\MCP_DataAccess.cfe` из распакованного комплекта.
4. Убедитесь, что расширение активно и имя — `MCP_DataAccess`.
5. Примените изменения конфигурации базы данных.
6. Назначьте пользователю MCP роль `MCPData_ОсновнаяРоль` вместе с его
   обычными бизнес-ролями.

Основная конфигурация и режим поддержки не изменяются.

### 3. HTTP-публикация

Опубликуйте базу локально в Apache с модулем `wsap24.dll` именно версии
8.3.27.2214. Listener должен слушать только `127.0.0.1`. В публикации:

- включите HTTP-сервисы расширений;
- разрешите сервис `MCPDataService` с `rootUrl=mcp-data`;
- отключите OData, web-сервисы и остальные HTTP-сервисы;
- на уровне Apache запретите публикацию целиком и разрешите только точный путь
  `/hs/mcp-data`.

Базовый URL имеет вид:

```text
http://127.0.0.1:<порт>/<публикация>/hs/mcp-data/
```

Проверка:

```powershell
$pair = 'Пользователь1С:Пароль1С'
$auth = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($pair))
Invoke-RestMethod `
  -Uri 'http://127.0.0.1:8080/mybase/hs/mcp-data/info' `
  -Headers @{ Authorization = "Basic $auth" }
```

Не сохраняйте этот пример с настоящим паролем в файле или истории команд.

### 4. MCP без мастера

Для диагностического запуска задайте секреты только в окружении процесса:

```powershell
$env:MCP_1C_DATA_USER = 'Пользователь1С'
$env:MCP_1C_DATA_PASSWORD = Read-Host 'Пароль 1С'
```

Запись Codex:

```toml
[mcp_servers.onec_data]
command = 'C:\MCP1CData\mcp-1c-data.exe'
args = [
  '--base-url',
  'http://127.0.0.1:8080/mybase/hs/mcp-data/'
]
```

Codex должен быть запущен из процесса, унаследовавшего эти переменные.
Для постоянной установки используйте мастер и DPAPI-launcher: он не требует
хранить пароль в TOML.

## Обновление

1. Скачайте и полностью распакуйте новый установочный комплект.
2. Закройте сеансы базы.
3. Запустите новый `Setup.cmd` с тем же каталогом базы и именем профиля.
4. Создайте новую DT-копию или явно подтвердите использование внешней.
5. Мастер установит CFE и бинарники новой версии в отдельный каталог,
   проверит публикацию и обновит управляемый блок Codex без дублей.
6. Перезапустите Codex и проверьте версию через диагностику.

## Диагностика

| Симптом | Что проверить |
|---|---|
| `отсутствует payload\mcp-1c-data.exe` | Архив запущен без полной распаковки; распакуйте весь ZIP |
| DT-копия завершилась с кодом 1 | Закройте сеансы, проверьте пользователя Конфигуратора и журнал в `backups` |
| `Отказано в доступе по пути httpd.exe` | Антивирус, блокировка скачанного ZIP, права `%LOCALAPPDATA%` и запущенный файл |
| HTTP 401 | Имя/пароль пользователя 1С неверны; это не отдельные реквизиты MCP |
| HTTP 403 | Нет роли маршрута, бизнес-права/RLS запрещают объект или Apache закрыл путь |
| HTTP 404 | Не опубликован сервис расширения, неверны публикация/root URL или CFE не активировано |
| Порт занят | Выберите другой начальный порт `8080–8099`; мастер пропустит зарезервированные |
| `QUERY_COMPILE_FAILED` | Используйте возвращённые позицию и текст ошибки, затем повторите `get_query_schema` |
| `truncated=true` | Результат неполный; сузьте фильтры или используйте агрегат |
| `LATEST_DOCUMENT_INCOMPLETE` | Один из доступных видов не проверен в пределах бюджета; результат намеренно не выдан |

Пароли не должны отправляться в issue. При обращении приложите обезличенный
журнал установки, версию платформы, версию CFE и код ошибки.

## Сборка из исходников

Требуются Windows, Go 1.25.x, 1С 8.3.27.2214 с `wsap24.dll` и одноразовая
файловая база для сборки CFE.

```powershell
.\build.ps1 `
  -Version 1.2.0 `
  -GoExe 'C:\path\to\go.exe' `
  -PlatformBin 'C:\Program Files\1cv8\8.3.27.2214\bin' `
  -BuildInfoBase 'C:\path\to\disposable-base'
```

Скрипт выполняет Go-тесты и vet, self-test установщика, загружает исходники
расширения, выполняет `UpdateDBCfg` и `CheckConfig`, экспортирует CFE, повторно
загружает его и формирует ZIP с манифестом SHA-256.

Отдельно:

```powershell
C:\path\to\go.exe test ./...
```

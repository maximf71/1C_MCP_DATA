# MCP1CData 1.2.0 — подробная установка

Это руководство описывает установку отдельного MCP `mcp-1c-data`, расширения
`MCP_DataAccess`, локальной публикации Apache и профиля Codex.

## 1. Поддерживаемая среда

- Windows 10/11 или Windows Server;
- файловая информационная база, содержащая `1Cv8.1CD`;
- платформа строго **8.3.27.2214**;
- компонент платформы «Модули расширения веб-сервера»;
- файл `C:\Program Files\1cv8\8.3.27.2214\bin\wsap24.dll`;
- конфигурация, допускающая подключение расширений;
- локальный Codex Desktop/CLI;
- свободный loopback-порт в диапазоне 8080–8099.

Совместимость с другими версиями платформы, серверными базами и Linux в
релизе 1.2.0 не заявляется. Установщик останавливается до изменения базы, если
точная версия платформы или `wsap24.dll` не найдены.

## 2. Что подготовить

### Каталог базы

Нужен каталог файловой базы, например:

```text
C:\1C_Bases\БГУ 2.0
```

В нём должен находиться файл `1Cv8.1CD`. Выбирать каталог шаблона,
дистрибутива конфигурации или резервной копии нельзя.

### Пользователь MCP/RLS

Это обычный пользователь из списка пользователей информационной базы 1С.
Именно под ним будут выполняться запросы. Ему нужны:

- роль расширения `MCPData_ОсновнаяРоль` после установки CFE;
- обычные бизнес-роли конфигурации;
- настроенный RLS, если видимость должна зависеть от организации или другого
  разделителя данных.

Отдельный логин, создаваемый MCP-сервером, не существует.

### Пользователь Конфигуратора

Нужен для выгрузки DT, загрузки CFE, `UpdateDBCfg` и `CheckConfig`. Он может
совпадать с пользователем MCP. Если у пользователя MCP недостаточно прав,
заполните отдельные поля пользователя Конфигуратора.

### Резервная копия

Рекомендуется оставить создание DT включённым. Отключение допустимо только при
наличии свежей проверенной внешней копии. Мастер потребует отдельного
подтверждения и запишет факт пропуска в журнал без секретов.

## 3. Загрузка комплекта

1. Откройте страницу
   [GitHub Releases](https://github.com/maximf71/1C_MCP_DATA/releases).
2. Скачайте `MCP1CData-Setup-1.2.0.zip`.
3. При необходимости проверьте SHA-256, опубликованный в описании релиза.
4. В свойствах ZIP нажмите «Разблокировать», если Windows показывает такую
   кнопку.
5. Полностью распакуйте архив в отдельный каталог.

Структура должна содержать:

```text
MCP1CData-Setup-1.2.0\
  Setup.cmd
  Install-MCP1CData.ps1
  manifest.json
  README-INSTALL.txt
  payload\
    mcp-1c-data.exe
    mcp-1c-data-launcher.exe
    MCP_DataAccess.cfe
```

Ошибка об отсутствующем `payload\mcp-1c-data.exe` означает, что запущен
неполностью распакованный комплект.

## 4. Поля мастера

| Поле | Назначение |
|---|---|
| Файловая база | Каталог с `1Cv8.1CD` |
| Название профиля | Понятное имя базы; из него формируется безопасный ID |
| Пользователь MCP (RLS) | Обычный пользователь 1С, от имени которого читаются данные |
| Пароль MCP | Пароль этого пользователя 1С; шифруется DPAPI |
| Пользователь Конфигуратора | Необязательно; для DT и установки CFE |
| Пароль Конфигуратора | Необязательно; не записывается в профиль или журнал |
| Начальный порт | Первый проверяемый порт 8080–8099 |
| Создать резервную копию DT | Включено по умолчанию |
| Добавить профиль Codex | Включено по умолчанию; изменение подтверждается отдельно |

Если поля Конфигуратора пустые, мастер использует учётную запись MCP и для
административных действий.

## 5. Автоматическая установка

1. Закройте 1С и Конфигуратор для выбранной базы.
2. Запустите `Setup.cmd` от того пользователя Windows, который запускает
   Codex. Запуск от другого пользователя приведёт к созданию DPAPI-секрета,
   недоступного обычному сеансу Codex.
3. Заполните поля мастера.
4. Оставьте DT-копию включённой либо подтвердите её осознанный пропуск.
5. Нажмите «Установить».
6. При запросе на изменение Codex выберите «Да», если профиль нужно добавить
   автоматически.
7. Дождитесь сообщения об успешной установке. Не закрывайте окно во время
   `UpdateDBCfg` и `CheckConfig`.
8. Перезапустите Codex.

### Последовательность действий мастера

1. Проверяет путь базы и точную платформу.
2. Проверяет наличие `wsap24.dll`.
3. Сверяет SHA-256 всех файлов payload с `manifest.json`.
4. Создаёт DT-копию, если флаг включён, и проверяет ненулевой файл.
5. Загружает `MCP_DataAccess.cfe`.
6. Активирует расширение через `UpdateDBCfg`.
7. Выполняет `CheckConfig -AllExtensions -CheckModules
   -IncorrectReferences -HandlersExistence`.
8. Устанавливает или переиспользует Apache Lounge 2.4.68-260617 Win64 VS18,
   проверяя закреплённый SHA-256.
9. Выбирает свободный и не зарезервированный порт.
10. Создаёт отдельные VRD, Apache config, PID и error log для профиля.
11. Ограничивает listener адресом `127.0.0.1` и разрешает только
    `/hs/mcp-data`.
12. Создаёт профиль и шифрует логин/пароль Windows DPAPI CurrentUser.
13. Проверяет `/info`, пользователя, платформу и `read_only=true`.
14. Запускает launcher с `--check`.
15. Делает резервную копию `~/.codex/config.toml` и добавляет отдельный
    управляемый MCP-блок.

Существующие MCP-профили и публикации не заменяются. Совпадающие запущенные
бинарники и проверенная установка Apache переиспользуются без перезаписи.

## 6. Результат установки

```text
%LOCALAPPDATA%\MCP1CData\
  Apache24\
  backups\
  bin\1.2.0\
  credentials\
  logs\
  profiles\
  publications\
```

Управляемый фрагмент Codex выглядит примерно так:

```toml
# >>> MCP1CData:<profile-id> >>>
[mcp_servers.onec_data_<profile-id>]
command = 'C:\Users\<user>\AppData\Local\MCP1CData\bin\1.2.0\mcp-1c-data-launcher.exe'
args = [
  '--profile',
  'C:\Users\<user>\AppData\Local\MCP1CData\profiles\<profile-id>.json'
]
# <<< MCP1CData:<profile-id> <<<
```

Открытого пароля в TOML и JSON-профиле нет.

## 7. Проверка

### В 1С

Откройте «Администрирование MCP» → «Диагностика MCP-доступа к данным».
Ожидаются:

- платформа `8.3.27.2214`;
- расширение `1.2.0`;
- правильный пользователь 1С;
- число доступных объектов метаданных;
- успешная компиляция безопасного тестового запроса;
- сообщение, что привилегированный режим не используется.

### Launcher

Путь к профилю можно проверить без запуска STDIO-сервера:

```powershell
& "$env:LOCALAPPDATA\MCP1CData\bin\1.2.0\mcp-1c-data-launcher.exe" `
  --profile "$env:LOCALAPPDATA\MCP1CData\profiles\<profile-id>.json" `
  --check
```

Ожидается JSON с `"ok": true`. Команда не печатает логин или пароль.

### В Codex

После перезапуска задайте:

> Покажи самый последний документ, который доступен мне в 1С. Укажи тип,
> номер, дату, проведение, фильтры, количество строк и усечение.

Корректный результат имеет `complete=true`, одинаковые `readable_document_types`
и `scanned_document_types`, фильтр удаления и `truncated=false` либо явное
предупреждение об усечении.

## 8. Ручная установка CFE

Если публикация и MCP-бинарники настраиваются отдельно:

1. Создайте DT-копию.
2. Откройте базу в Конфигураторе 8.3.27.2214.
3. Откройте список расширений конфигурации.
4. Загрузите `payload\MCP_DataAccess.cfe`.
5. Проверьте имя `MCP_DataAccess` и версию 1.2.0.
6. Активируйте расширение и примените изменения конфигурации базы.
7. Назначьте пользователю MCP роль `MCPData_ОсновнаяРоль`.
8. Сохраните его обычные бизнес-роли и RLS — они определяют доступ к данным.

Установка расширения не создаёт пользователя и пароль. Эти данные берутся из
существующего списка пользователей информационной базы.

## 9. Ручная публикация и подключение MCP

Локальная публикация должна использовать `wsap24.dll` версии 8.3.27.2214,
слушать только loopback и публиковать HTTP-сервисы расширений. Включите только
`MCPDataService` с корнем `mcp-data`, отключите OData и остальные сервисы.

Проверочный URL:

```text
http://127.0.0.1:<порт>/<публикация>/hs/mcp-data/info
```

Для разового запуска сервера:

```powershell
$env:MCP_1C_DATA_USER = 'Пользователь1С'
$env:MCP_1C_DATA_PASSWORD = Read-Host 'Пароль 1С'

& '.\mcp-1c-data.exe' `
  --base-url 'http://127.0.0.1:8080/mybase/hs/mcp-data/'
```

Для Codex укажите тот же executable и `--base-url` в `config.toml`. Переменные
окружения должны быть унаследованы процессом Codex. Для постоянной работы
предпочтительнее профиль мастера и DPAPI-launcher.

## 10. Обновление существующего профиля

1. Скачайте новый полный комплект.
2. Закройте сеансы базы.
3. Запустите новый мастер.
4. Выберите ту же базу и то же имя профиля.
5. Создайте новую DT-копию.
6. Завершите установку и перезапустите Codex.

Новая версия бинарников размещается в своём каталоге `bin\<version>`. Мастер
обновляет управляемый блок профиля и не дублирует его.

## 11. Удаление

Автоматического удаления с восстановлением базы нет, поскольку оно могло бы
повредить другие профили и публикации.

Для удаления одного профиля:

1. Закройте Codex.
2. Удалите только управляемый блок `MCP1CData:<profile-id>` из
   `~/.codex/config.toml`.
3. Остановите Apache-процесс именно этого профиля по его config/PID.
4. Удалите соответствующие файлы из `profiles`, `credentials` и
   `publications`.
5. При необходимости удалите расширение через список расширений 1С.

Не удаляйте общий `Apache24` и каталог `bin`, пока их используют другие базы.
DT-восстановление выполняйте отдельно и только в явно выбранную базу.

## 12. Типовые ошибки

### Обязательная DT-копия завершилась с кодом 1

- закройте все сеансы, включая HTTP-соединения и Конфигуратор;
- проверьте учётную запись Конфигуратора;
- откройте `.dt.log` из `%LOCALAPPDATA%\MCP1CData\backups`;
- убедитесь, что хватает места;
- пропускайте копию только при наличии проверенной внешней резервной копии.

### Отказано в доступе к `httpd.exe`

- разблокируйте скачанный ZIP до распаковки;
- проверьте карантин антивируса;
- убедитесь, что файл не удерживается сторонним процессом;
- запускайте мастер под тем же Windows-пользователем, который владеет
  `%LOCALAPPDATA%\MCP1CData`.

### HTTP 401

Проверьте имя и пароль существующего пользователя информационной базы. Пароль
MCP — это пароль пользователя 1С, а не отдельный ключ.

### HTTP 403

Проверьте роль `MCPData_ОсновнаяРоль`, обычные роли, RLS и Apache allow-list.

### HTTP 404

Проверьте активацию CFE, публикацию HTTP-сервисов расширений, имя публикации и
корневой URL `mcp-data`.

### Установщик не может скачать Apache

Проверьте доступ к `apachelounge.com`, прокси и TLS Windows. Скачанный файл
всегда сверяется с закреплённым SHA-256; подменять архив другой сборкой нельзя.

### Результат усечён или неполон

`truncated=true` означает необходимость сузить фильтры. Ошибка
`LATEST_DOCUMENT_INCOMPLETE` означает, что полный охват не подтверждён; сервер
намеренно не выдаёт частичный документ как последний.

## 13. Безопасное обращение за помощью

К issue можно приложить:

- версию Windows и точную версию 1С;
- обезличенный журнал из `logs`;
- код ошибки;
- имя маршрута;
- число доступных/проверенных типов без строк бизнес-данных.

Не публикуйте пароли, файлы `credentials`, профиль целиком, DT-копию,
персональные строки, полный ответ 1С или `config.toml` с другими секретами.

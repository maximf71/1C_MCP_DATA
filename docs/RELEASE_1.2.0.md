# MCP1CData 1.2.0

Готовый установочный комплект для Windows и файловых баз 1С на платформе
**8.3.27.2214**.

## Установка

1. Скачайте asset `MCP1CData-Setup-1.2.0.zip` ниже.
2. Полностью распакуйте ZIP в отдельный каталог.
3. Закройте сеансы выбранной базы.
4. Запустите `Setup.cmd` от пользователя Windows, который запускает Codex.
5. Оставьте создание DT-копии включённым и дождитесь успешной проверки.
6. Перезапустите Codex.

Подробности: [руководство по установке](https://github.com/maximf71/1C_MCP_DATA/blob/main/docs/INSTALLER_GUIDE.md).

## Новые возможности

- `get_latest_documents` принимает `responsible`, `organization`, `posted`,
  `date_from` и `date_to`. Ссылочные фильтры задаются парой `metadata` + `uuid`;
  даты — в RFC3339. Диапазон включительный.
- документы с одинаковой максимальной датой возвращаются вместе, до 20 строк;
  `truncated=true` запрещает считать этот список полным.
- `get_document_table_parts` читает одну табличную часть документа по
  `Document.Name`, UUID и точному имени табличной части. Максимум — 200 строк.
- `search_metadata` ищет по точному техническому имени реквизита (`field`) и
  поддерживает стабильную пагинацию (`cursor`, `next_cursor`, `has_more`).
- `validate_query` возвращает очищенную и ограниченную 500 символами ошибку
  компилятора 1С вместо общего сообщения.

## Безопасность

Все новые операции помечены read-only/idempotent, используют обычный сеанс
пользователя 1С и `ВЫБРАТЬ РАЗРЕШЕННЫЕ`. Привилегированный режим не включается.
Фильтрованный глобальный поиск сохраняет лимиты: один параллельный вызов, два
в минуту, до 1000 типов документов и внутренний бюджет 20 секунд. При неполном
охвате результат не возвращается.

Отдельная серверная операция `get_latest_documents` уже проверяет все виды
документов, поэтому общий тайм-аут произвольных запросов не увеличен.
